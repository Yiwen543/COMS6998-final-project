## 新版本如何修正

`controller_done_scoring_v4.json` 在新评分执行前登记。`controller_done_case_v4.py` 统一处理绑定、原始日志解析、判分和汇总；`controller_done_grade_v4.py` 的新回放与日志复用路径都调用这个内核。

- 每轮固定保留 18 个正确控制和 144 个故障轨迹对。参考结果、候选、样例或证据缺失时，仍保留对应记录并标为未决。旧的非评分记录原样携带，不再读取其不存在的结果路径。
- 检查资格行文件 SHA、规范化行 SHA，以及“标签周期数 = 尝试回放周期数 = 行数”。终点必须对应最终 post。原始 MON 样本、属性位、报警、unknown 和检查次数也重新核对；错配、不完整或畸形证据不能获得检出分。
- 两条路径都明确报告每类故障的 `FAIL_with_oracle_unknown_pairs`。总未决数包含参考 unknown、候选 unknown、不完整回放和非评分记录。包含终点的统计名称带 `including_marker`，普通采样报警单独统计。
- 检出类型按普通 safety 与终点有限义务分开。有限义务仍是 ANY_SLOT / UNATTRIBUTED 的样例级检出，不能说某个槽位已经证明某一类义务。

先前的见证 v3 不变：参考只评价到 post(S−1) 的物理前缀，选中报警发生于 pre(S)。两者不直接构成候选误报或选中报警的参考确认。失败位置、类别和 unknown 继续保存；本阶段没有重跑旧形式任务或 DUT 仿真，也没有 GPT oracle 补丁。
