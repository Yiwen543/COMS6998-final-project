# Draft monitor ABI v3: explicit finite evaluation boundary

This adds one readonly monitor input, `trace_done`, to the v2 public-pin ABI.
The DUT interface, RTL, fixed stimuli and specification_v2.md are unchanged.
This is a new evaluation-interface version; it never changes old candidate code,
old observations, old scores, or the independent reference checker.

`trace_done` is generated by the evaluator, never the DUT or candidate. It is0
at every pre sample and at all post samples except the final post sample, where
it is1. The marker is combinationally observed after the final rising edge and
its settled DUT outputs; it creates no extra clock edge or DUT transaction.
The model receives this exact rule publicly. No hidden fault identity, expected
response or final observation is encoded in the marker.

A candidate may enable finite completion checks at `trace_done`. At that sample
the independent reference is called on the same full rows with
`require_drained=true,min_tail=128`. Definite failures retain priority over
unknowns; insufficient tails remain UNRESOLVED, never automatically PASS.
The marker does not grant permission to assume responses arrived correctly.
It only makes the declared end of finite evaluation observable to a passive
monitor, including when a source offer remains blocked until evaluation ends.

Safety remains checked at all normal pre/post samples. Reset still cancels the
same obligations. `trace_done` is not reset and is not a DUT input. All existing
six-slot/body16000byte/state8192bit/passive-clock boundaries remain.

Any short-depth formal safety projection must explicitly state
`trace_done=0`; it cannot claim to prove finite completion. A depth24 activation
check cannot establish a128-cycle quiet-tail condition. Finite completion and
sampled safety must be reported separately.

Status: offline ABI qualification draft. No live-generation permission or new
independent model result is implied by this document.
