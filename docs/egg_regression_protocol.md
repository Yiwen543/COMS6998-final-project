# Frozen protocol: semantic regression and proof reuse for LLM RTL properties

## Research question

On ordered, typed candidate revisions, does scoped equality saturation provide useful checked equivalence evidence, reusable dependencies or lower work compared with equally informed non-egg methods? Do not assume acceleration or an improvement in LLM generation. This experiment replays archived real API outputs and predeclared controlled revisions, not a new online model experiment.

## Scope and outcomes

Input is the archived three-trial transaction task, nine violation (alarm) predicates over a trusted transaction-history snapshot. The three initial replies are independent generations, not actual successive repairs. Existing recorded same-arm repairs are reported separately. Controlled revisions and guard changes are not LLM outputs. The domain is the declared unsigned, two-state snapshot variables, not arbitrary SystemVerilog temporal semantics, not necessarily reachable RTL states. Both endpoint expressions are compared under the same *current* guard. An old guard is provenance only; a changed guard cannot authorize stale evidence. Feasibility must hold. A new alarm is stronger if the old alarm implies the new one but not conversely; weaker is the converse. Report `equivalent`, `strengthened`, `weakened`, `incomparable`, `unknown`, `infeasible`. Directional SAT witnesses are independently evaluated on typed snapshots. Egg merges prove equivalence, not non-equivalence or one-way implication.

Use the fixed workload generated by `egg_regression_workload.py` from the archive without querying equivalence to choose inputs. Group requests by ordered revision round, property, and exact typed guard, keeping first-seen group order inside a round. The explicit local TLAST requests are not additional independent real model generations, and cannot be called whole-domain proofs merely because one guard passes. Count actual initial, actual history, local context and controlled cohorts separately, with identities separated from nonidentical strings. No retry to select favorable model outputs.

## Comparison arms

* **Incremental SMT + equivalence connectivity**: fixed typed formulas, exact guard-specific solver with cached directional queries and equivalence path reuse from already established equivalent comparisons; canonical structural identity is free. No dependence on egg facts.
* **Ordinary + common facts + connectivity**: same primitive, independently certified ground facts as egg, persistent group-local Boolean propositional direction checks. Abstract SAT is not a typed witness; only unresolved directions fall back to exact incremental SMT. Reuse already established equivalent comparisons within the same scope. No cross-guard proof transfer based merely on cache keys.
* **Pairwise egg**: independently run each nonidentity pair with *the same union ground facts* as the shared engine; checked equality or typed incremental SMT fallback. No graph/path reuse between requests, but same shared primitive-query cache for all fact-based methods.
* **Shared egg + proof reuse**: one graph per round, property and guard for the remaining nonidentity pairs, with the same rule inventory and facts. Before constructing a graph, consult previously checked proof paths (including reverse/transitive paths). Cross-guard reuse requires reauthorizing every used ground equality from certified current facts; missing evidence blocks reuse, not a claim of inequality. Independently replay paths and every newly extracted proof. Use exact incremental SMT fallback for unresolved candidates. Count direct proof/exact identity/path reuse/fallback separately, including when an equality exists but the graph misses it. Shared graph is not a persistent incremental Rust graph across contexts; persistence is the portable checked proof store. Do not claim it implements Versioned E-Graphs.

For both egg methods: fixed 23 Boolean schemas, each independently truth-table checked, 20 iterations, 20,000 e-nodes, 5 seconds per graph; no unbounded retry. Total graph budgets differ with number of graphs, which is an outcome, not equal total search capacity. A batched graph with multiple requested edges stops once all merge or saturation/resource limit. Every merge must produce an independently replayable derivation or structural identity. No graph merges across guard IDs. Common fact discovery involves primitive comparator facts only; do not assert complete endpoint equality as a ground rule. Fact SMT cache uses exact scope/guard, typed source and obligation, including negative query outcomes; report its cost separately, not a saving unique to egg. No semantic verdict may be inferred from missed equality saturation.

## Evidence and accounting

Fresh typed direct solver oracle (no operational cache; separate from each arm) independently grades every request, checks expected frozen labels, and audits all returned verdicts. Retain groups, source endpoints, facts, receipts, graphs, proof paths and fallback receipts, plus summary. All-identity batches check guard feasibility only (no primitive fact discovery or native graph). Count query misses/hits, graphs, steps, ground dependency use, path/transitive/cross-guard reuse, blocked reuse, exact identity and fallback; record runtime separately for fact discovery, native engine, checker, other methods and offline oracle; timings include process launch where applicable. Graph time is not formal end-to-end verification time. Costs attributable to shared common facts must be added for each fact-based arm when comparing to direct solver. Offline independent audit costs reported separately. In addition, compare concrete observations on existing RTL trace corpus, with unknowns and unreachable/not observed contexts distinct. The archive is not changed. No new API calls, no claim replay improves the model. These are controlled functional-verification experiments; no DUT modifications outside preexisting trace controls.

Accept conclusions only if all method verdicts match fresh typed oracle and checked proofs do not falsely merge distinct predicates (unless explicitly unknown and escalated). Report failures/unknown, scope and cohort limitations, not a selective success metric. A gain of shared egg over pairwise egg alone is not proof of gain over strong non-egg baselines.
