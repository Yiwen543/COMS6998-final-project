# Milestone 3 · AXI 帧事务验证真实在线实验结果

2026-11-24 的 MacBook 实验完成了 3 个独立无辅助初稿和 18 次后继修订，均由 `gpt-6.1-sol/low` 实际返回。**三个初稿在任何反馈之前已经达到 9/9；每个 trial 内后续六次回答逐字符保留原初稿。** Egg 的实际证书机会为零。因此该实验验证模型能够直接生成更复杂的事务属性，却没有提供测量 proof-carrying feedback 修复收益的样本，不能将零机会解释成 egg 证明失败或有效加速。

| 配置 | 实际值 |

独立审计重建 209 个实验文件，确认每个无辅助初稿只实际请求一次、全部三臂都继承各 trial 自己的相同初稿；9 个非末轮修订回复均由本臂后继请求真正消费。三个初稿请求正文逐字一致，未包含已知错误 seed 或参考表达式、反例、证书。开发反馈仅来自原版与 F02/F05，F01/F03/F04/F06 仍留出评分。实际语义、轨迹和用量回执均重算，无新模型 API 请求；没有因初稿已经通过而从统计中丢弃 trial。

|---|---:|---:|---:|---:|

21 份模型回复均解析/类型合法，无模型语法失败，无结构域内不等价性质或超时。它们只是三个自然生成的不同完整候选组：每 trial 的 1 份初稿和 6 份修订逐字符相同。三 trial 的摘要分别为 `a27b7cf30a76…`、`f7013984523b…`、`813143691640…`。三个初稿有 19 种不同的“性质×完整字符串”，并非复制了完全相同的参考结构；只有其中两种与独立参考表达式原文一致。不同写法主要来自合取结合、夹紧长度分支顺序和 `data_last` 在恰好长度四处的等价分支选择。所有后继回答没有任何一个完整表达式被修改，因而不能用 21 作为独立初稿样本数。

例如，Trial 1 的 `data_last` 用 `data_n < 4` 与 `data_n >= 4` 分支，Trial 2/3 写为 `data_n <= 4` 与 `data_n > 4`。当 `data_n=4` 时两种表达都恰好要求 `data_index=4`；在八字节边界和输出游标限制下仍忠实于规格。独立验证证明这些并不是被有限轨迹偶然接受的错误写法。

## 2. 检验事务规格：完整位宽与实际 RTL 语料

重新对全部 21 批输出（189 个属性判断）运行独立完整位宽 XOR，全部 UNSAT。三个独立初稿的 27 个属性在去掉历史结构域约束之后，再做两个完全自由的 well-typed pin/ghost 赋值空间的 XOR，仍全 UNSAT。这个控制确认成功不是由于结构域约束偶然掩盖了语义差异，但不把符号赋值域等同 RTL 可达性。

每个不同初稿重新在所有 21 条原版/变异轨迹上评分，完全重现对应归档。每批 12,712 个 PRE/POST 观测快照、9 属性，共 114,408 次性质比较，全部确定，与参考精确匹配。与前一轮只有五项局部断言时不同，此处原六种内部功能变异都被事务属性检测到。所有三种不同初稿还在**额外未参与在线闭环的九条端口级灵敏度轨迹**独立评分；每批 49,032 次判定、277 次参考报警均匹配、零误报漏报。这只是额外样本复验，未计入 F01–F06 的真实内部变异数。

所有 trial 的第一次合格发生在第 0 轮，因此每臂**达到首次合格所需增量修订 tokens 均为 0**。若单独考虑任一臂从头得到结果，需要共享初稿的 5,746 tokens；实际实验全局只计算这一初稿用量一次。固定预算的 18 次追加调用消耗 86,418 tokens（93.77%），没有修改候选；这是预先承诺的对照运行，不是获得合格结果的必要费用。

每 trial Raw/Ordinary/Egg 的新增 feedback size 均为 4,716 / 4,741 / 4,763 UTF-8 bytes；Egg 相比 ordinary 仅新增空字段的 22 bytes。实际首个修订输入每 trial 增加 6 tokens，第二修订随历史累计增加 12，三个 trial 合计增加 54 tokens（约 0.19%）。这**不是发送真实证明的 overhead**，与之前五属性 live 含 13 份证明的 token 差额不能直接比较。

总缓存读取 41,788 tokens，缓存写入 37,868（全部 30 分钟 TTL）。试验 2、3 的初稿存在共享前缀缓存读取，仍然是不同 response ID 和不同完整初稿。439 个 reasoning tokens 全部在三次无辅助初稿中（125、205、109），已包含在输出计数；18 次后继均实报 0 reasoning。没有发票与端到端延迟记录，不把 token 当成实付金额或耗时。

## 5. 追加对照：不修复而审计实际模型候选的等价性

尽管实际 LLM 修订没有证书机会，三个初稿出现了不同但合法的自然写法。因此独立做一项**后验等价证明覆盖**实验，而非修改或重新运行在线实验。对三个初稿同一性质的所有无序对共 27 个机会，其中 9 个字符串完全相同；18 个非相同出现次数去重为 12 个具有不同原文的组合。只对这个非相同组计证明覆盖，不把原文恒等当作非平凡证明。

各方法使用相同的、经完整位宽 Z3 独立认证的原子等价/互补替换。这里只用不带历史结构域的自由 well-typed 引脚及 ghost 原子，不把完整候选等价作为规则注入。普通基线对相同抽象原子做规范化 + 命题 XOR，外加独立位宽 oracle。三个通用 egg 配置沿用旧六条、加结合律、再加交换与分配律，均在相同 20 轮/20,000 节点/5 秒预算下目标合并即停止，且逐个证书独立重放。

| 固定的 12 个不同原文组合 | 成功证明数 | 非平凡 Egg 步数 | 停止原因 |
|---|---:|---:|---|
| 独立完整位宽 Z3 | 12/12 | — | 全部 UNSAT |
| 普通规范化/命题 XOR | 10/12 | — | 10 UNSAT、2 抽象 SAT |
| Egg 旧六条 | 0/12 | 0 | 12 饱和未证 |
| Egg + 结合律 | 8/12 | 11 | 8 目标合并、4 饱和未证 |
| Egg + 交换/分配 | 10/12 | 14 | 10 目标合并、2 节点受限 |

所有 19 个去重“初稿性质、表达式”对原 reference 的直接完整位宽 XOR 也均 UNSAT（覆盖 27 个 trial×性质）。两个未由抽象证明的组合都属于 `data_last`：在恰好 `data_n=4` 时，`data_index=data_n` 与 `data_index=4` 只有条件成立后才等价。独立布尔原子丢失了这一位宽依赖，使两者在抽象域 XOR SAT；这不是实际 typed counterexample，也不能通过增加无条件布尔等价规则修复。此对照说明 egg 可对真实模型的不同合法写法提供具名改写证明，但未超过同样抽象的普通基线。它没有进入 21 次既有模型请求，也没有额外模型调用；规则配置是后验分析，不用来声称模型收益。

最宽配置新增的两对证明来自 `header_adjusted` 的析取交换律；14 步只使用了合取结合和析取交换，虽然装载了分配规则但实际证明没有使用。原始 Mac 归档与清理归档的复跑，除用时及归档哈希，全部判断与证明图逐项一致。

## 6. 研究解释与下一步

本次九项事务规格对 RTL 的检测范围确实比五条局部监视器更广，但对当前强模型**仍有任务天花板**。主要难点之一——跨拍原始历史、数据和 Header 独立游标、复位后的上下文——已由固定正确 ghost tracker 实现；模型只需要把明确的自然语言事务义务转换成类型化的逻辑谓词。即使逻辑比上一轮复杂，当前模型在 3/3 初稿上完成了翻译。实验能够支持“该模型能在给定可信 tracker 和明确规格下合成这九条监控公式”，不能支持“模型自主合成整个事务 scoreboard”或“egg 对错误修复有增益”。初稿样本数只有 3，并不能排除别的任务或初稿自然出错。

下一轮不建议再次花费固定 21 次调用重复同一任务。若继续关注 LLM，真实的复杂状态更新合成更有判别力：向模型提供原始握手引脚与自然语言规格，不直接供应已经构造的正确事务游标更新；让模型生成受限可执行的 ghost 状态转移、队列/epoch 更新及监视器（与固定独立 oracle 进行状态转移和跨周期验证）。Egg 可研究验证条件之间的等价、状态更新 guard 证明、归一化或诊断，不以人为制造模型错误为成功门槛。是否能取得额外收益需要独立新实验。可在下一轮协议中事先规定第 0 轮合格即不分叉修订，记录所有成功和失败初稿、不重抽至出现错误；只在剩余待验证错误的共同候选上开展配对修订，节省真实 API 支出。
