# Frozen protocol: dependency-driven scoped verification proof reuse

## Question and scope

Prior shared Egg discovers the full signed primitive-fact forest before consulting its proof store. Can a checked historical derivation be reused by establishing only its actual prerequisites under the current guard? Measure query count, coverage, replay, invalidation and cost against strong non-Egg alternatives; a smaller fact inventory or a native graph skip alone is not evidence of faster RTL verification or better LLM generation.

All sources are the existing typed two-state transaction snapshot language, with fixed unsigned widths and the existing 23 independently checked Boolean rewrite rules. Only exact typed equality/implication is transferred; changed type schemas, unknown facts or infeasible guards cannot authorize a proof. These are monitor relations, not an unbounded DUT proof. No new API calls or RTL modifications.

## Frozen workloads (separate fresh stores/caches per workload)

* **matrix:** all 224 requests and the exact order/grouping from `egg_regression_workload.py`, including identities and real-vs-controlled labels. No sampling by outcome.
* **live:** one deduplicated six-assessment chronology from the latest audited nine-response live archive: reference vs carried monitor (preflight), then reference vs actual qualified reply, for each of 4→5→4. Verify all three arms used the same carry and qualified text at each stage, retain their source receipt IDs. Do not count the three identical histories as independent proof opportunities. Distinguish wrong-scope carry from LLM reply failure.
* **ladder (controlled):** use the original actual T1 `data_last` reference P; Q = P AND `N<8`, R = P AND `N<9`. In order: P↔Q and Q↔R under N=4 (one group); P↔R under N=5; R↔Q under N=5; P↔R under N=8; P↔Q under N=8; P↔R under N=9; Q↔P under N=4; P↔Q under N=5. This predeclared chain tests reuse across guards, reverse and intermediate endpoints not present in the current pair, a blocked derivation despite true target equality, actual non-equivalence, and return to a certified context. A separate final infeasible guard `(ult data_n 0)` must not pass as an ordinary feasible equality. Actual old proof choices may differ; do not force a particular path or outcome other than the independent semantic classification.
* **portfolio-01/03/05/09 (controlled scaling):** form an aggregate alarm P as the left-associated OR of the first 1, 3, 5, or 9 distinct archived T1 properties, putting `data_last` first and the other property names in lexical order. Q = `(and (ult data_n 8) P)`. Compare P/Q at guards N=4, 5, 6, 7, 8, then 4. N<8 comparisons are equivalent; N=8 is a weakened alarm because P can report a violation while Q is false. These are controlled combinations of real monitor formulas, not new model outputs or independent RTL designs. The initial proof cost and invalidation are included; no warm-start subsidy.

The source archives, generated plan and protocol content are hashed before the first run. All expected labels follow existing archived certificates or the predeclared construction; a fresh complete typed directional oracle independently grades every comparison and is never an operational input. History/workload/arm state is isolated. Requests are grouped by `(round,property,guard)` within each workload; batch proof lookup sees only the prior group's store, not later requests or newly created intra-group proofs. The direct SMT baselines are sequential and may use an earlier result even inside the same group, as in the previous strong baseline. No arm uses a future result.

## Arms

1. **SMT-exact:** same exact-width incremental solver, directional caching, and previously established equivalence connectivity within exactly the active guard. Independently check guard feasibility, even for identities. No primitive enumeration.
2. **SMT-subscope:** same solver plus sound guard inclusion for previously established whole-target equivalence (for the supported single-variable unsigned threshold syntax, interval inclusion is exact; `true` includes any feasible guard). This stronger baseline also uses reverse and transitive equality paths. No arbitrary extrapolation of an old result to a different guard.
3. **Egg-eager:** original full fact discovery before store lookup; same shared native graph batching, one per group for pending distinct pairs; store all checked paths. All-identity groups have only feasibility query. Scope membership may block reuse even when a missing prerequisite is still true. Exact typed fallback if no proof.
4. **Egg-cache:** dependency-first path search, consult only already-certified exact-context leaf receipts, no fresh targeted dependency query. Skip full forest only when no graph is needed. Otherwise discover the same full group inventory, then try original forest-based lookup before native graph. This ablation separates laziness and cache hits from actual cross-context re-certification.
5. **Egg-dependency:** dependency-first path search; for a historical edge, query exact `G_current ∧ XOR(typed_leaf_left,typed_leaf_right)` only for its used ground equalities not in the exact-context cache. Positive, negative and unknown are distinct. Same-scope previously verified receipts are reusable without fresh solving; cross-scope requires current exact receipt. Validate stored atom/endpoint/rule/schema signatures and proof ID, rebind current rule names, independently replay the derivation (including inverse steps and intermediate terms not in endpoint syntax). A blocked path invalidates no target verdict. Try alternative prior paths, then unchanged full group fact discovery and original lookup before native search; no optimistic acceptance. Retain every checked and failed dependency obligation and fallback. A proof store is a portable historical proof graph, not an incremental native E-Graph implementation.
6. **Ordinary-dependency:** strong non-Egg comparator sharing the same fact discovery, exact-context query cache, path selection, targeted typed re-certification, and lazy fallback. For fresh abstract equivalences, collect Z3 Boolean assumption unsat cores for both directional queries and use their union as sufficient primitive dependencies; check the reduced Boolean XOR before storing. This solver-derived core is not an equality-saturation rewrite trace. Reuse valid cores with current typed dependencies, or exact-scope typed equality paths when full-width fallback was needed; unresolved directions use typed solver. Report its Boolean checks separately, not as full-width checks. This arm intentionally uses an actual dependency certificate rather than just syntactic normalization.

For each proof-assisted group the dependency lookup uses shortest deterministic paths first (prefer all exact-scope edges; otherwise shortest path over the topological graph, ID-stable tie-break). Once an edge is blocked on the first non-UNSAT/missing leaf, exclude it and try another path. Check only candidate-path dependencies, cache exact obligations, and reuse validated edges within a lookup. Histories with unrelated endpoints do not query facts merely because edges exist. If any nonidentity request remains unresolved after lazy lookup, discover the **same full group fact inventory** as eager (including all original group sources) to isolate optimization from a weakened fact engine. No partial proof accepted. Native engine limits/rules match the previous study (20 iters/20k nodes/5 s, outer timeout 30 s); graph generation and proof replay are separate. No new condition beyond the fixed workload changes the strategy after observing results.

## Measurements and acceptance

Report per workload and arm: correct classifications, identities, equivalence proofs/paths (not conflated with typed fallback), same/cross-scope reuse, blocked paths and reason, previously unseen prerequisite queries and cached hits, proof steps/core dependency sizes, full-discovery groups, native graph calls, typed full checks, primitive/guard checks, Boolean checks, all actual typed checks (including feasibility, discovery, targeted re-certification and fallbacks), separate oracle/audit cost, wall time and exact solver/graph budgets. Record and independently re-solve/replay archived evidence and store history; reject any false equivalence or other classification mismatch, including infeasible guards. A missing dependency is not a claimed false equality. Check the exact source/guard of each dependency, including SAT rechecks, and separately count prerequisites outside current endpoint vocabulary.

Evaluate both total costs (including initial creation and changed guard) and where new mechanism avoids broad fact enumeration. A win over eager Egg or the cache-only ablation does not establish unique superiority over ordinary-core reuse or direct SMT. No extrapolation of repeated portfolio scenarios to natural LLM errors, proof of general RTL correctness, or end-to-end API speed/tokens. Prior live transcript and offline data are unchanged.
