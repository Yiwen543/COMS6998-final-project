# 四字节边界的 TLAST 监控式是否在真实 RTL 上一致

本实验取三次真实 API 试验的首轮回复中的 `data_last` 公式，分别记为 T1、T2、T3。T1 把长度等于 4 的情况归入常规输出分支，T2 和 T3 把它归入短帧分支。已有的 21 条原始及功能变体轨迹确实覆盖这个边界。三种写法在所有 12,712 个可评分的 PRE/POST 快照上判断一致。

`data_n` 是数据通道当前指向的输入帧**已握手接收的字节数**。它可能是尚未收完的前缀。有效呈现还要求复位无效、`m_valid=1`，且当前输出字节有已接收输入或合法补零作为依据。独立接收方施加背压时，正确性仍然适用。

| 主轨迹上的分支 | 可评分 PRE/POST 快照 | 有效数据呈现 | TLAST 参考报警 | C08 误报 / 漏报 |
|---|---:|---:|---:|---:|
| 已接收长度小于 4 | 7,268 | 934 | 8 | 0 / 0 |
| 已接收长度等于 4 | 853 | 815 | 4 | 52 / 4 |
| 已接收长度大于 4 | 4,591 | 3,330 | 22 | 0 / 0 |

小于 4 的 7,268 个快照中有 6,086 个在当前数据游标没有输入帧，有效呈现数已排除这些快照。各行统计的是采样点，同一数据拍可能出现在 PRE、POST 或多个背压周期。

**C08 是监控式负对照。** 它将 T1 中唯一的 `(uge data_n 4)` 改为 `(ugt data_n 4)`，使已接收四字节且已经收完的帧在有效呈现第四拍时失去 TLAST 要求。原始 RTL 单独产生了 8 次误报。F03 的 `backpressure` 轨迹在第 197 个时钟的 POST 给出漏报实例，T1 观测到缺失 TLAST，C08 放过了该错误。

额外的 9 条端口诊断轨迹按相同的三种分支分别有 414、363、1,506 次有效呈现；C08 在等于 4 的分支产生 24 次误报。主轨迹和补充轨迹分别计数，复用的三条原始轨迹只计一次。

## 符号结果与重放

对每一对公式，脚本在原有结构域上用全位宽 Z3 求解异或，还分别限制 `data_n < 4`、`data_n == 4`、`data_n > 4` 再求解。T1 对 T2、T3 的八个查询全部为 `unsat`。T1 对 C08 在无分支限制和等于 4 时为 `sat`，另外两个分支为 `unsat`。结构域描述事务记录与游标的一致性。实际可达的分歧由上述原生轨迹给出。

从仓库根目录运行以下命令。需要 Python 和本项目固定版本的 `z3-solver`；本次重放使用 Z3 4.16.0。物理输入均已归档，无需模型、API 密钥或新仿真。输出参数须指向新目录。

```sh
python scripts/check_txn_context_physical.py \
  --controls results/milestone3/frame-diagnostic-faults \
  --output /tmp/frame-txn-context-check
python -m unittest discover -s tests -p test_check_txn_context_physical.py
```

脚本读取归档并核对三份真实回复的 SHA-256，按输入和输出握手重建快照，用独立的逐拍判定逻辑复核参考结果。遇到 X/Z 时，它会检查两侧在**同一组未知信号补全**上的异或；两侧各自不可判定仍有可能在所有补全中相反。专项测试覆盖这个情形和未知 `m_valid` 的情形。归档结果给出了各分支、各轨迹的计数、首次误报及漏报的完整引脚和事务上下文，以及可直接交给 Z3 的 12 份 SMT 查询。[核查脚本](../scripts/check_txn_context_physical.py) · [实测明细](../results/milestone3/frame-txn-context-physical/summary.json) · [符号查询](../results/milestone3/frame-txn-context-physical/queries.json)
