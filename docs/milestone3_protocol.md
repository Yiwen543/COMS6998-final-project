# Milestone 3 experiment protocol

Base commit `71e99c4cbef9768abc1b20d4d344eaee8594db59` on `perf/egg-compute-fast-v1`. This workload and these comparisons were selected before collecting the timing series. Use the checked-in eight-way fixed-priority arbiter, all sixteen source-mapped priority guards, the existing initial stimulus and checker, and its four independent probes. Keep the upstream DUT unchanged. The three saved engine inputs and the FIFO test3 runner named in the Milestone 2 report are absent from this branch.

1. **Engine cost.** Generate two expressions for each priority guard from the same RTL. Compare the same 32 expressions with either zero design-specific rules or nine rules certified in QF_BV. On each input, compare the frozen v1 `spanning` binary with the candidate `indexed` binary. Both use the six original Boolean rewrites, identical egg limits and a fresh process for each observation. Alternate their order for 12 paired trials per profile after one warmup per binary. Measure process wall time and the internal stages in milliseconds. Require saturation and exact equality of every result field except elapsed time, including evidence endpoints and proof text. Count how many source/alternate pairs are recognized by each rule set.
2. **Verification cost.** Cross three guard sources (raw source, v1 spanning, indexed) with two first-witness searches (existing scalar, bit-parallel). Run all six arms in rotated order for six trials per profile. Use original compact/expanded guards in one profile and the Z3-certified alternate forms in the other. Every trial performs initial and refined Verilator simulations on the original DUT. Charge input extraction, engine invocation and output handling, coverage processing, witness search and replay to the active loop. Report compilation and rule certification separately as one-time setup. No whole-result cache or simulation reuse.
3. **Quality and failure accounting.** Keep exact ordered legal stimuli, per-target witnesses, checker counts, and all original source counters, including zeros. Compare physical observations across arms and with the stored reference where compatible. Fail the run on mismatches, missing targets, unfinished simulations, solver unknowns or inconclusive egg stops. A detected violation in the original DUT is an expected observation, and must be reproduced.
4. **Interpretation.** Compare v1 vs indexed at fixed witness method to assess egg, scalar vs bit-parallel at fixed engine to assess witness search, and raw vs egg to assess the incremental price of semantic evidence. Report component and inclusive timings, positive or negative. Repetitions measure timing variation on one RTL fixture. The study does not estimate cross-IP generality, live LLM token cost or four-state equivalence.

**Reference repository addition.** A companion repository became available during implementation. Before measuring the engine series we added all three paths listed in fast-v1's own benchmark instructions, taken from `Yiwen543/COMS6998-final-project@e94172a1bd5e9b138b5fc3da01554edb3052ce52`. Apply the same 12 paired trials, binaries and exact proof gate to Controller, SPI and I²C, without regenerating their archived rules. This is a cross-input engine check. Physical RTL measurements still use the pinned arbiter.
