# 验证证据维护实验设计

目标是让一个独立审阅程序复核已经发布的 guard 等价证据，定位其依赖，遇到变更时区分“旧证明失效”“仍有其他证明”“有真实反例”。无需改变既有验证结果或追求运行时间优势。

- 针对固定 AXIS Controller 的全部 148 个目标和 281 条已通过位向量验算的规则，复核已有 70 条证明边的每一步；逐条撤回全部 281 条专用规则，每种情形重跑 egg，检查旧证明能否保留、修复或暂时无法重建。撤回证书不构成 RTL 行为变化。比较显式规则图的可解释路径以及普通结构归一化。
- 以原有 16 个 arbiter 源 guard 与替代表达式为合同。在隔离副本中分别从 override 非零检测器省略一个输入位（全部八位各一次），另测等价写法和只改变数据输出的对照。逐位复核检测器的完整真值表。保留有效前提支持的证明，只对依赖失效前提的合同单独发起查询；全部 16 项的直接查询作为独立参照。对照普通记录规则名的语法树替换，分别统计规则重验与合同重验。另用硬件回放区分 guard 合同和输出正确性。
- 对一个确切的零命中原始计数器，检查 egg 是否能把独立证明过的不可满足性传递给原 guard，记录模型、计数器身份和使用的前提。用专门扩大父条件、使该分支可达的改动检查豁免能否撤销。保留原始覆盖率分母。
- 这些是给定设计、规则、作用域及预先限定编辑的机制实验。没有用户研究，不能从步骤数推断人力或时间节省；仅在有独立可重放的证据时保留验证结论。
