# AXI 帧事务监视器的配对修订实验

本协议在查看新实验结果前冻结。研究问题是：当模型必须从自然语言规格自行构造跨拍、跨通道的事务监视器时，给同一份反例和最小充分条件补充可重放的 egg 证明，能否让模型更早修好监视器，或者用更少的模型 token 达到同等验证质量。一次 trial 是一次独立的初始生成；同一 trial 内三个分支构成配对。

## 监视器必须自行推导什么

被测对象仍是固定的 AXI Frame Length Adjuster。只把源端 `valid && ready` 握手接受的字节记入当前复位周期的帧历史，用源端实际接受的 LAST 确定输入帧边界。数据输出和头部输出分别用各自通道观察到的握手与帧边界推进游标，两个接收端可以独立停顿。PRE 使用本时钟边沿之前的历史，POST 使用该边沿更新后的历史。发生复位后使用新的事务历史；复位清除的判断观察实际 POST 引脚。

模型接收自然语言规格、九个字段的名称和带类型的原始输入接口。接口可给出帧存在性、已接受长度、输入是否结束、原始历史字节、观察游标和原始输出引脚。禁止提供“预期输出字节”“预期最后一拍”“应置位的标志”、预先比较好的答案或参考表达式。默认输出帧长度下界为 4 字节，上界为 8 字节；输入按已冻结测试环境限定在 1–12 字节。短帧在末尾填零，长帧仅传输前八个字节。源端尚未结束的已接受前缀，也可能已包含当前要发送的字节。

| 性质 | 从历史与采样引脚判断的违规事件 |
|---|---|
| `data_entitlement` | data valid 呈现当前数据拍，但所指帧、已接受的前缀或允许的帧尾填充不足以支持这拍。 |
| `data_payload` | 已有依据的数据拍呈现的字节与当时可用的原始字节或零填充不同。 |
| `data_last` | 已有依据的数据拍上，实际 LAST 与夹紧后帧尾的位置不符。未闭合前缀也受最大输出长度约束。 |
| `header_entitlement` | header valid 呈现头部，但独立头部游标处还没有已接受完毕的输入帧。 |
| `header_original` | 可呈现的头部报告的原始长度与对应输入帧实际接受的字节数不同。 |
| `header_adjusted` | 可呈现的头部报告的调整后长度与该原始长度夹紧至 [4, 8] 的结果不同。 |
| `header_flags` | 可呈现的头部对填充或截断的标记与输入长度不符，恰好 4 或 8 字节属于边界正常情况。 |
| `reset_clear` | 复位边沿后的输出 valid 仍置位。 |
| `drain_complete` | 已到指定的排空检查点，仍有输入或输出活动、未完成帧或未消费的事务。 |

模型输出九个**违规条件**。错误握手产生的状态也进入观测，以便监视器能发现 DUT 本身的错误。参考判定独立从规格推导，候选求值不调用参考代码。逻辑域中的数据、头部、valid 等 DUT 输出引脚均保持自由，禁止用参考规格约束输出。合法的类型、位宽和历史记录结构条件单独列出。可满足的符号反例需要回放具体赋值；其 RTL 可达性另由实际 RTL 和形式环境判定。

## 固定的三组和反馈边界

1. 每个真实 trial 先对同一份自然语言规格和类型接口发起**一次**无辅助请求。此请求没有错误 seed、参考实现、开发反例、诊断或证明。原样保留模型初稿及用量，三组继承完全相同的初稿。初稿若无效，三组接收同一验证错误；若初稿完美，计入第 0 轮成功并照固定预算执行后续轮。不因难度、首轮错误数或证书是否可生成筛选、重抽或丢弃 trial。
2. 每个组独立保留自己的后续回答与相应反馈，修订轮数、模型、推理设置、输出预算一致。匹配候选使用同一个参考判定和开发反例。raw 收到共同反馈；ordinary 在其基础上获得从**当前候选自身**的符号化真假条件求出的最小充分文字；egg 的全部共同字段与 ordinary 一致，另给经独立回放的 cube 证明。对负例解释候选的否定。先验证条件符合实际样本，并用有类型的蕴含查询独立验证充分性。egg 只证明同一组文字固定时有符号候选可化为真，其余原子保持自由。分别计数实际送入下一请求的完整证明、结构恒等和因资源/预算不可提供的证明。
3. 开发反馈仅使用原版及此前冻结的 F02、F05 开发轨迹，确定性选取可判定的反例。需要时，用独立有类型的符号反例补充，并标明来源。留出的 F01、F03、F04、F06 的标识、轨迹、样本、得分和独立参考公式不得进入任何模型反馈。所有组与初始生成均可看到完成任务所必需的公共规格。
4. 离线 fixture 在运行前于代码固定错误起点和各轮回复，三个分支使用相同脚本化序列。它用于测量反例、诊断和证明能否在真实评分后进入正确的下一条请求，及复核归档可否拒绝篡改。fixture 的真实 API 调用计数为 0，模型 usage 为空。在线模式必须保存每次实际的 provider 回包。两类运行分别归档。

## 判定与报告

- **表达式和 RTL 评分。** 分别报告九个性质的解析/类型错误、独立有类型 XOR 的 SAT/UNSAT/UNKNOWN，以及 PRE、POST 或排空点上相对参考的正确报警、漏报、额外报警和无法判定的样本。物理数据使用固定 Icarus 运行的原版和六个独立 RTL 改动，覆盖长度扫描、独立背压、复位周期三种轨迹。公布原版误报和每个故障被哪些性质识别，并把原独立事务 checker 的结论单独记录。遗漏的稳定性语义等仍需独立 checker 检查。对某性质或边界没有天然故障的情形，可附加定向灵敏度控制，单独计分，不计入六个实际 RTL 故障。
- **有界形式检查。** 若另外在真实 RTL 上运行形式工具，逐项注明 RTL/监视器版本、ghost 状态容量、时钟与复位、输入假设、深度、求解器和 PASS/FAIL/UNKNOWN；可达性、证明范围和证人依这些边界解释。离线轨迹中出现的有限样本、独立符号域中的全赋值等价、原版 RTL 的有界无反例分别报告。超时、范围外、未知值不计作证明。
- **比较单位。** 先统计无辅助初稿的正确性质数与第 0 轮通过率，再按 trial 报告各组首次完全合格的轮次、到该轮的 provider input/output/total、预算全部用完的用量、最终的质量。三组共享的初始调用在整体开销中只算一次，同时列出它与各分支增量；比较单组从头完成时可显式把同一初始开销分别计入。cached 和 reasoning tokens 是相应父计数的子集。字节数、已传送证书数与本地计算成本单独记录。成功须九项判定全部合格、物理比较无漏报、额外报警或未知；语法错误同样占用该次调用。若预算内没有成功，首次成功轮及其代价为空，仍报告预算内实际用量。
- **可证伪的解释。** 保留所有 trial，比较初稿不合格者的配对修订结果，并同时报告其占全部 trial 的比例。初稿已经合格或三组都能立即修正，是任务区分能力的实测结果。失败案例区分候选表达问题、证明不可提供、反例是否真实可达与仿真覆盖不足。真实模型的结论仅适用于已观察的试次与工作负载。
