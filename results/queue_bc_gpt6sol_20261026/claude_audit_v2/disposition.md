# Claude Code Opus 5.5 cross-review disposition

Claude Code 2.1.310 made two read-only review passes using the exact `claude-opus-5-5` model: a blinded X/Y aggregate review, then an unblinded artifact review. The first pass cost about $0.21 and the second about $1.67 at the CLI's reported list-price basis. These are **Claude audit costs**, separate from GPT-6 Sol stimulus costs. The reviewer did not run the simulator or read the raw `.dat` files; our independent replay and byte comparisons provide that check.

| Finding | Disposition against frozen evidence |
|---|---|
| All 12 target costs are arithmetically consistent; 48 calls accepted without retries. | **Confirmed.** `target_costs.csv`, `rounds.csv`, `calls.jsonl`; `replay-verification.json` separately matched 48/48 rounds on 33 stable fields and 52/52 coverage files byte-for-byte. |
| C reached 41/41 one round earlier in two of six repetition-index comparisons, with the same final coverage. | **Confirmed, descriptive only.** Original target rounds B 3/4/4, C 3/4/3; variant B 3/3/3, C 2/3/3. The versions are one IP and model outputs are not paired deterministic samples. |
| The first-round X/Y coverage difference existed before feedback. | **Corrected.** Round 1 already receives raw coverage in B and raw coverage plus egg groups in C. `prompt-isolation.json` confirms six first-round prompt pairs have identical common fields and differ only by C's `egg_normalization`. Hence the difference can be an effect of the treatment or model variation; it is not a pre-treatment imbalance. |
| Repeated coverage profiles may be copied results. | **Rejected as a data-copy hypothesis.** Saved action batches differ: only 3/12 original-versus-variant B batches are identical and 0/12 C batches are identical. Byte-identical live/replay coverage files independently reproduce the profiles. The structural coverage space is coarse. |
| The C-only guard groups explain the observed earlier target. | **Not established.** The selected read/write cases are already covered after the first generated batch, so later C prompts contain empty `groups`. Variant rep 1 had identical B/C round-1 actions, and its earlier C threshold arose from a different round-2 choice. An empty semantic stub, stochastic response, or an indirect carryover can explain this; the result does not isolate a causal guard-group mechanism. A length-matched placebo and harder reachable targets are needed. |
| The 64 missing toggle directions are `queue_data[3][31:0]` transitions. | **Confirmed within this contract.** All 64 fourth-word bit directions have zero hits in the independent ceiling and final `.dat` files. The JSON action validator forbids a fourth write-only operation once the queue asserts full at three valid items; therefore no accepted sequence writes that word through the legal write-only path. They remain in the raw denominator. This is not a four-state or unrestricted-input reachability proof. |
| Checker may be vacuous or define away a capacity/overflow defect. | **Partly confirmed as a boundary limitation.** The checker uses `CAPACITY=DEPTH-1`, and the validator forbids a fourth write. The RTL asserts `full_o` after three writes because `FULL_THRESHOLD=DEPTH-2`; the natural-language spec says full is determined by an internal threshold, but does not give an independent numeric capacity. It also calls DEPTH the number of queue entries. These statements are ambiguous rather than a proved 4-entry requirement. Separate reference controls detect six injected faults spanning five checker categories under the chosen three-valid-item contract, so the checker is not vacuous; it does not validate unrestricted writes, fourth-slot behavior, or ambiguous almost-flag timing. Zero live failures cannot establish full-spec correctness. |
| Source joins and Z3 rewrite proof were not fully inspectable in Claude's read-only pass. | **Addressed with saved evidence, with stated limits.** `semantic-proof.json` now records all 22 independent Z3 member-to-reference Boolean proofs, source IDs/lines, event contexts, and separate read/write e-classes. `egg-evidence.json`, `typed-predicates.json`, the preflight equivalence log, and passing typed-predicate tests provide additional checks. This covers two-state combinational guards, not arbitrary four-state or between-clock sequential equivalence. |
| The generated `REPORT.md` rounds mean simulator counts to integers. | **Confirmed presentation defect only.** The exact target-cost CSV has 3.67 versus 3.33 simulations on the original and 3.00 versus 2.67 on the variant. The milestone result report and PDF show the non-rounded means. The frozen runner and saved measurements were not altered after the live run. |
| Claude's first pass could not validate checker, isolation, or replay from the aggregate packet. | **Confirmed.** The second pass inspected selected code and logs, while our separate replay, prompt diff, tests, and proof export address the quantitative claims. Claude's narrative is a second analyst, not the coverage oracle. |

**Final interpretation:** GPT-6 Sol's C arm had a small observed cost-to-target advantage in this one queue pilot; there was no final coverage advantage. Claude's audit and the raw artifacts do not support attributing the earlier target crossings specifically to the equivalent read/write guard groups. The checker covers a defensible but narrower three-valid-item contract, with capacity and almost-flag ambiguity explicit. The next controlled test should use independently specified capacity/flags, stronger reachable bottlenecks, at least two independent IPs, and a length-matched placebo semantic appendix.
