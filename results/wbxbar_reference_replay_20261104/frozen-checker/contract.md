# WBXBAR exact-history reference checker (candidate)

Scope: public pins of WBXBAR rev 2e8d3bc2, NM=2, NS=2, AW=8, DW=32, slave0 = (addr&0xf0)==0x00, slave1 = (addr&0xf0)==0x10. Rows are pre/post samples; only pre defines transfers, post is used for K1 reset outputs. Candidate only: independent controls, code review, freeze and replay are required before any B/C.

## Model
Exact explicit hypothesis set H per reset epoch; no quotient, partition, deduplication or pruning. Each hypothesis holds per-master FIFOs of live entries (identity, accept_row, master_epoch, reset_epoch, state unforwarded/forwarded/slave_acked/slave_erred/slave_canceled), a canceled pool of distinct members, orphans, per-slave forward FIFOs and a tag list. Row order: reset; CYC drop; master acceptances; slave CYC withdrawal; slave responses (bind to forwards from rows < c); slave acceptances (branch over every identity-equal candidate); master responses (K13, then K6/K7/K8 against entries from rows < c); association-free checks.

## Verdicts
scoped_pass, dut_violation, input_or_scope_invalid, unresolved only. Per-clause statuses are in counts.property_status (violated, env_violation_recorded, suspended, unresolved, not_activated, checked_not_refuted, prefix_checked_not_refuted, excluded_not_judged). scoped_pass means not refuted by the reference on this trace; it excludes K5 forward order and unproved characterization C1-C4, and is not proof of hidden ownership. Ownership per epoch is unique_by_elimination or indistinguishable(k) in counts.pending_alternatives.

Time-bounded precedence: e = first row with an environment violation; processing stops there. DUT violations before e stay final. At row e, pin-only DUT checks (K1, K2 slave payload, K3, K10, K13, rule 3.45) stay dut_violation; an ACK-driven K6 per-CYC count-bound failure also stays dut_violation, while an ERR-driven one (non-HR classification uses row-e inputs) becomes mixed_same_edge; association-dependent or row-e-input-dependent candidates (empty H, K4 per-identity count projection) become mixed_same_edge(dut_candidate, env), unresolved, with a note that no public ordering exists. counts.prefix_status gives prefix_scoped_pass / prefix_unresolved / prefix_dut_violation for rows < e.

## Unknown tags
post_abort_forward, unexplained_mapped_err, same_edge_response_after_abort, possible_starvation_err, starvation_attributed; any unclassified tag defaults to unknown. Tags carried by any surviving history are flushed to cumulative unresolved records at reset and batch end; reset never erases cumulative uncertainty.

Repeated HR ERRs during one held request are absorbed by branch B and are not judged; they stay unknown.

## Resource limits
Defaults MAX_HYP=4096, MAX_LIVE_PER_MASTER=64, MAX_CANCELED_POOL=256. The limits argument is for development selftests only and is validated; frozen callers pass rows only. On exhaustion: unresolved_on_limit(row, sizes), association clauses (K4 per-candidate, K6, K7, K8 attribution, K9 tags, K12) suspended for all masters until reset; still checked: K1, K2, K3, K10, K11, K13, rule 3.45, K4 per-identity count projection, per-slave response count, per-CYC ACK+non-HR-ERR bound. Counters are arbitrary-precision Python ints. counts.checked_scope reports suspended rows, fraction, exhaustion rows/sizes and effective checked rows.

## Declared exclusions
K5 order; C1-C4; liveness/latency/deadlines; payload while STB low, read-data lanes on requests, SEL-disabled lanes; write ACK data; reset-row master responses beyond K13/3.45; rule 3.05 sub-row reset length; formal F1-F8 unproved.

## Implementation decisions and blockers (not settled by the reviewed contract)
- B2 when the row-c entry was already forwarded in the same row: treated as orphan with post_abort_forward + starvation_attributed tags (scoped decision accepted by review; contract still silent, B1 always kept).
- Undefined i_sdata on a slave ACK is an env violation when the pin-derived per-slave forward FIFO head (WE sampled at slave acceptance) is a read, independent of hypotheses; this includes orphan/canceled reads, since rule 3.1.3.2 makes read data meaningful with ACK regardless of master attribution.
- Simultaneous o_mack&o_merr: rule 3.45 violation, response not attributed.
- K13 is not judged on the first trace row (no c-1).
- The K6 count bound uses acceptances from earlier rows of the current CYC (consistent with K6 retiring only rows < c).
- Master STB without CYC is not an acceptance and is not separately flagged.
- slave_canceled live entries at batch end are counted (non-obligation), not pending.
- A row with undefined DUT control output is a DUT violation and stops judgment (unjudgeable_row).
- Mixed same-edge pin-only vs association-dependent split as described above.

## Follow-up repair status (review R1-R8; not normative authority)
- P4 narrowed to ACK only; ERR-driven K6 count failures at row e are mixed_same_edge.
- A membership death at row e reclassified as mixed is not a refutation: tags of histories alive at the row start are flushed as open valid-prefix unknowns with original tag rows; discarded_epoch_evidence only holds deaths wholly before e.
- Exhaustion records disclose snapshot point and actual vs projected hypothesis count; death records disclose omitted dying-row tags per event.
- Scope accounting: counts.subobligation_activations and counts.clause_scope (units: K1 reset rows; K2 master held/accepted strobes and slave acceptances; K3 slave acceptances; K4 slave acceptances with defined projection, split count_projection vs candidate_consumption; K6 master responses with CYC high, split count_bound vs attribution; K7 master ACKs; K8 master responses; K9 CYC 1->0; K10 slave strobe rows and ACK&ERR rows; K12 batch end; K13 responses with CYC low). Raw activations are exposure, not coverage.
- Valid-prefix retention: at every first invalid-input boundary (env row, schema failure, mixed death) a snapshot of tags carried by histories feasible at the start of row e is flushed once (cleared after reset/batch-end/exhaustion flush to avoid double counting). K11 scope: K11_env_checks counts non-reset rows; schema validation and reset-row 3.20 checks are not instrumented.
- Still open: K5, C1-C4, F1-F8, timeout/cancellation bounds, both_interfaces_pending, rule 3.05 sub-row reset.
- N1/N2 repair: undefined pre DUT control output stays a dut_violation (K10) and stops judgment, with unjudgeable_row. It is reported as counts.termination_boundary / termination_reason, distinct from input_validity_boundary. Unit: the explicit history set at the start of that row (no processing of the row occurs). If active, it is closed once with reason terminated_unjudgeable_dut_output: its tags are flushed as open unknowns, pending live entries give pending_at_unjudgeable_row (K12 unresolved, not a batch-end activation), and slave-canceled ones are counted. If suspended or dead, nothing is reflushed, so suspension tags and refuted disclosures are not double counted. prefix_status is derived as for input boundaries, and non-violated activated clauses report prefix_checked_not_refuted. Later rows, including resets, are not processed.

## Reporting clarifications (review T2/T4/T5; documentation only, no semantic change)
- T2 row numbering on termination: for the epoch closed with reason terminated_unjudgeable_dut_output, pending_alternatives.closed_at and the cycle of the pending_at_unjudgeable_row record are the last processed row (c-1). counts.termination_boundary is the unjudged row c, where judgment terminated on undefined DUT control output. The closed state is the explicit history set at the end of row c-1, which is the start of row c. closed_at must not be read as the terminated row. If the undefined DUT control output occurs before any reset, there is no active epoch, so no closure record is emitted.
- T4 counts.checked_scope.rows_beyond_input_boundary: despite its name, this is total_rows_in_trace - processed_rows, i.e. the number of unprocessed rows. It applies at either boundary: the first invalid-input boundary (counts.input_validity_boundary) or the termination boundary (counts.termination_boundary). It is nonzero on the termination path even when input_validity_boundary is null. A row that fails schema or validity checks, or that terminates on undefined DUT control output, is not processed and is included. A row in which an environment violation is detected during processing counts as processed and is not included. The field name is unchanged.
- T5 counts.clause_scope.<clause>.unknown_tag_records: this counts only entries in the unresolved list whose item is one of the classified tag kinds. Those kinds are post_abort_forward and unexplained_mapped_err (K9 and K8), possible_starvation_err and starvation_attributed (K6), and same_edge_response_after_abort (K13). Every flush that contributes such entries is included: reset, batch end, pre-suspension, valid-prefix boundary and termination. It excludes pending_at_batch_end, pending_at_unjudgeable_row, unresolved_on_limit, mixed_same_edge, unjudgeable_row and unclassified tags, as well as counts.discarded_epoch_evidence (refuted-history disclosure, not in the unresolved list). It is a historical count of unknown-class tag records. It is not the total of unresolved diagnostics, not a clause status (see property_status) and not coverage.

## Proposed decisions for fresh independent review (not normative authority)
- P1 (F1) [SUPERSEDED IN PART: at any first invalid-input boundary, including a mixed death, row-start tags are flushed once as open valid-prefix unknowns, not refuted]: On exhaustion, tags of the histories feasible immediately before suspension are flushed to unresolved (class unknown, marked pre-suspension) and a pending_alternatives record with reason suspended_on_limit is emitted. On membership death, tags carried by histories alive at the start of the dying row are recorded in counts.discarded_epoch_evidence, explicitly as refuted-history disclosure: not open uncertainty, not a hidden-owner fact, never masking the fault; a membership_dead record is emitted. Tags created within the dying row itself are not captured (disclosed limitation).
- P2 (F2): Per-clause activation units in counts.clause_activations: K1 reset rows; K2 master held/accepted strobes plus slave acceptances; K3/K4 slave acceptances; K6/K8 master responses with CYC high; K7 master ACKs; K9 master CYC 1->0 transitions; K10 slave strobe rows plus ACK&ERR rows; K11 nonreset rows; K12 batch-end closure; K13 responses with CYC low. A non-violated, non-suspended, non-unresolved clause with zero activations reports not_activated. Zero activation is never a DUT violation and never a formal or cover claim.
- P3 (F3): Displays capped at 16 histories and 8 witnesses with explicit histories_total/displayed/omitted and witness shown/total/omitted; no history is pruned for reporting.
- P4 (F4) [SUPERSEDED: narrowed to ACK only; ERR-driven count failures at row e are mixed_same_edge]: An ACK-driven K6 per-CYC count-bound failure uses only DUT response pins and acceptances from rows < c within the current CYC, so at row e it is kept as dut_violation under precedence rule (2). The K4 per-identity projection counts row-c master acceptances (permitted same-row forward), so at row e it remains mixed_same_edge. Membership death at row e remains mixed_same_edge.
- P5 (F5): B2 on an entry already forwarded in its acceptance row: kept as orphan with post_abort_forward + starvation_attributed tags; branch B1 is always also kept, so no verdict depends on B2 alone. Undefined i_sdata on a slave ACK: superseded by the association-free pin FIFO-head rule above (integer drivers cannot emit None). Undefined pre DUT control output: DUT violation, judgment stops (unjudgeable_row). First-row K13 not judged (no c-1). All remain scoped decisions pending review.
- Events list is always empty; no recovery event or ownership proof is invented.
- Identical histories are not merged, so exhaustion may occur earlier than with a quotient; this is reported, never pruned.
