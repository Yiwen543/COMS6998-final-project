# 帧监视器反馈实验的固定起点

三组候选均针对原来的八位 AXIS 包装模块及五个违例监视器。先固定 15 个起始公式及修订顺序，再独立进行全位宽验证和波形评分。起始集合的 SHA-256 为 `d1e0336ae61e200934675df1bdda4067e260c27e77435c45456e44acbe7bbcaa`。观察器比较相邻上升沿之前的引脚值；头部监视义务从 valid 呈现时开始，保持义务包括上拍 valid 且尚未握手的最后一拍。[起始公式和修订函数](../../../scripts/egg_frame_pc_seeds.py)

| 监视目标 | historical · 原先的五项错误 | mixed · 两种常见错误叠加 | corner · 容易漏测的情形 |
|---|---|---|---|
| 数据保持 | 用当前 ready 判断上一拍是否停顿 | 用上拍输入端 valid 判断输出端义务，同时忽略 TLAST 变化 | 看到上拍 TLAST 就停止检查，可能提前放弃尚未握手的末拍 |
| 头部保持 | 忽略原始长度字段变化 | 只有当前仍 valid 才核对载荷，并漏检 truncate 位 | 将两个标志的独立变化错误写成“同时变化”才报警 |
| 填充标志 | 把原长正好为 4 也当作短帧 | 等到头部握手才检查，并拿调整后长度推断原帧是否过短 | 仅将 1–3 字节视为过短，遗漏 16 位接口值 0 |
| 截断标志 | 把原长正好为 8 也当作过长 | 等到头部握手才检查，并误用含等号的上界 | 检查器仅跟踪原长不超过 255 的头部，较长帧完全漏检 |
| 调整后长度 | 始终要求调整后长度等于原长 | 只在握手时检查输出是否落入 [4,8]，允许错误的区间内结果 | 三段式检查在原长正好为 8 时没有匹配分支 |

**评分。** 对每一项，Z3 在完整的 8/16 位、两个采样点的二态引脚空间内查询参考与候选的 XOR。15 个问题都得到 SAT，且具体引脚赋值被重新求值确认。回归测试另用独立书写的布尔义务和位向量 `If` 实现并复核全部种子和修订。每组参考与候选合并后的布尔抽象最多 12 个不同的原子。[逐项赋值及评分](audit.json) · [独立测试](../../../tests/test_egg_frame_pc_seeds.py)

| 组别 | 全位宽不等价属性 | 开发数据有明确差异 | 全部原生采样有明确差异 | 仅发现符号差异的属性 |
|---|---:|---:|---:|---|
| historical | 5/5 | 4/5 | 4/5 | 头部保持 |
| mixed | 5/5 | 4/5 | 5/5 | 无；长度检查在独立诊断组漏报 48 个报警采样 |
| corner | 5/5 | 0/5 | 0/5 | 全部五项 |

这里的物理差异可为漏报或误报。评分保留 30 个不同的设计/场景组合，各组只有一份原版。开发数据包括原版、F02、F05；其余四个原变异和三个端口灵敏度对照仅在独立评分中使用。mixed 数据保持比较另有 20 个无法判定的采样，未计入漏报或误报。普通帧的输入长度范围是 1–12，因此对 0 或大于 255 的头部输入取得符号反例，不足以判断原 DUT 在这些轨迹下的行为。其余无物理差异的属性同样只说明给定的采样未区分两式。[原生变异波形](../frame-faults/README.md) · [端口灵敏度对照](../frame-diagnostic-faults/README.md)

**确定性修订。** 第 0 轮返回种子，第 1 轮固定替换数据保持和填充标志两项，第 2 轮替换所有五项。如果驱动执行第 3 轮，继续返回相同的最终候选。修正的具体拼写按哈希读取历史归档中的 `egg/round-02/response.json`。这些修订预先写定，各个反馈组收到相同候选。其已修正项数为 0、2、5、5，不能据此推断模型学习效果。此次起点审计的模型请求数为零。

使用仓库中的历史转录归档、两套冻结观测，以及 Python 3.12 和 z3-solver 4.16.0。以下命令在项目根目录运行，`--audit` 需要一个尚不存在的输出文件。该命令独立导出起点的全位宽反例、物理漏报/误报/未知数、源语料和最终归档拼写的哈希。

```bash
python3 -m unittest discover -s tests -p 'test_egg_frame_pc_seeds.py' -v
python3 scripts/egg_frame_pc_seeds.py --audit /tmp/frame-seeds-audit.json
```
